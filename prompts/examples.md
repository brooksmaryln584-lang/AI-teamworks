# 提示词示例

版本：0.2.0-preview。用途：启动、分工、复核和恢复。验收：输出能对应任务卡、文件差异和实际检查。方括号内容必须先替换。

以下通用模板仍适用于 Codex、Claude Code 和其他已完成能力验收的客户端。

## 1. 只读摸底

```text
请先阅读 README.md、AGENTS.md 和项目相关记忆，检查当前 Git 状态。
目标：[本次目标]。本轮只读，不安装工具、不修改文件。
输出：规则来源、项目入口、已有改动、可用检查命令、信息缺口。
只根据实际文件和命令报告；不要把历史记录当作当前状态。
```

## 2. 执行者

```text
你是本任务执行者。请按 AGENTS.md 建立唯一会话身份和会话记录。
任务卡：docs/task.md。
目标：[明确产物]。
可修改：[精确文件或目录]；只读：[依赖范围]。
验收：[可观察结果及检查方式]。
禁止：[任务相关限制]。最多 6 轮，预算：[金额或运行时长上限]。
先检查协作状态并领取范围；coord 离线时记录 fallback，确认互斥后再写入。
完成后列出实际差异、检查命令、退出码、已知限制，并新建提交报告。
你的状态最多为 submitted；独立复核由另一会话完成。
```

## 3. 独立复核者

```text
你是独立复核者，使用与执行者不同的会话身份。
任务卡：[路径]；执行者报告：[路径]；审查版本：[提交或产物哈希]。
只读实现文件，可写：[你自己的新报告路径]。不直接修正实现。
先验证报告引用的文件版本，检查实际差异，运行与任务风险相称的检查。
按严重程度说明问题、位置、触发方式和证据；未发现问题也要写检查范围与局限。
只有证据充分才标记 verified；有问题则要求执行者修正并重新提交。
```

## 4. 两个执行者分工

```text
请依据任务卡先划分互斥文件范围：会话 A：[范围]；会话 B：[范围]。
共有接口由 [指定会话] 负责，另一方只读。
先核对依赖；遇到共同文件需求时停止该文件修改并交接所有权。
各自维护自己的身份和租约，不替另一会话登记或完成任务。
按任务卡完成后分别提交证据，由后续独立会话或人工审查集成结果。
```

## 5. 中断后恢复

```text
请读取 [任务卡]、[最近交接]、[稳定记忆]，并检查当前文件和 Git 状态。
建立新身份，区分已验证事实、旧记录和仍需核对的事项。
先确认任务是否仍由其他会话持有，再领取剩余范围。
从 [检查点] 恢复，剩余轮次：[数值]，预算：[上限]。
不要重复安装、覆盖既有修改或延用失效的独立复核结论。
```

## 6. 发布准备

```text
请为 [目标仓库] 整理可审阅的发布包，只包含已批准公开的文档和模板。
检查相对链接、真实工具来源、许可、凭据、本机路径和历史运行数据。
先给出准确发布文件清单、验证结果和未完成项。
公开推送前按任务授权核对仓库、可见性和内容；目标不明确时先询问。
```
