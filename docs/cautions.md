# 注意事项与排错

版本：0.1.0-draft。用途：说明本方案的边界和常见故障。验收：排错依据当前证据，修复局限于授权范围。

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| AI 没有遵守规则 | 启动目录、文件名、加载来源 | 确认 AGENTS.md；Claude Code 检查 CLAUDE.md 导入 |
| coord 无法连接 | 服务是否运行、地址和端口是否一致 | 检查 coord status；离线时明确记录，无法确认互斥则暂停写入 |
| 任务被其他会话领取 | 任务 ID、身份与租约 | 不覆盖对方范围，重新分配或等待交接 |
| 切换 provider 后失效 | 当前配置由谁维护、实际生效入口 | 保存脱敏证据，由配置所有者修复；不反复覆盖多个配置来源 |
| Windows 命令受阻 | 命令解析到 ps1、cmd 还是 exe | 使用实际存在的 cmd/exe 入口，不放宽全局策略 |
| 声称完成但没有产物 | 报告是否绑定任务、差异和命令 | 退回补充证据；进程退出不等于任务验收 |

共享工作目录内不要让多个会话同时切换分支、执行 reset 或清理文件。可使用独立 checkout/worktree 分隔代码修改，但最终合并仍需验证接口和冲突。

API 域名、操作类型、预算和副作用范围应在任务中写明；不要把预算声明误称为服务端硬上限。实际请求是否受限取决于工具和服务配置。

只把必要代码发送给已批准的模型服务。不要公开认证文件、provider 数据库、绝对本机路径、客户资料、原始聊天和运行日志。若凭据已进入公开 Git 历史，需要撤销或轮换凭据；单纯删除当前文件不能消除既有暴露。

一个组件负责一份实际配置：安装器负责二进制，provider 管理器负责其配置，项目规则负责流程。切换工具不是修复所有兼容性问题的通用办法。

本教程基于一套个人中枢工作方式整理，未证明适用于所有 IDE、操作系统和团队规模。上线前应在练习项目完成验收；第三方安装与使用遵守其官方说明。
