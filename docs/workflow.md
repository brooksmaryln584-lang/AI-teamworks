# 协作流程

版本：0.1.0-draft。用途：约定从任务到交接的证据链。验收：任一完成结论都能定位到身份、文件版本和检查记录。

## 一次任务的六步

1. 用户定义结果、读取范围、修改范围、禁止事项、风险和验收标准。
2. 执行者读取规则及相关记忆，检查当前文件与 Git 状态，填写会话记录。
3. 检查协调状态并领取范围；不同执行者不能同时拥有相同文件。coord 只原子领取任务，不强制锁文件。
4. 在边界内实现，按影响运行检查。记录命令、退出码和观察到的结果；无法运行的检查如实说明。
5. 稳定产物提交另一会话复核。提交后到复核完成前冻结该产物，或使用固定提交/哈希；修改后重新复核。
6. 复核通过后关闭任务，新增交接报告，把仍有效的决定写入稳定记忆。

## 两套状态不能混用

| 本指南状态 | 意义 |
| --- | --- |
| working | 指定会话正在处理任务 |
| submitted | 执行者已提供产物与证据，可能尚未独立复核 |
| verified | 不同身份检查了所引用的同一产物版本 |
| closed | 本任务的协调账本完成关闭 |

coord 自己的 pending、claimed、completed 是调度状态。本指南的 verified 是审查结论，需要报告支持。一个任务关闭不能推出所有 Codex 或 Claude 会话都已完成。

## 记忆分层

共享中枢保存版本化规则；项目记忆保存架构决定与约束；交接保存当前检查点；coord 保存临时任务状态。每次恢复先核对实时文件，不把历史报告作为当前环境证明。

## 失败与恢复

租约过期、范围冲突或身份不清时停止写入。测试失败时记录失败、缩小定位范围，并在任务轮次内修复。新会话以交接和当前差异恢复，不伪造旧会话身份。默认最多 6 轮，预算按任务约定；达到上限后保留产物并请用户决定下一步。

提示词和 Markdown 记录属于流程约定。需要自动门禁时，应另行实现字段校验、文件范围检查及运行器权限约束，并提供测试；本包附带字段校验器，但未实现文件范围和运行权限强制门禁。
