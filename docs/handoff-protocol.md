# 跨模型交接协议

版本：0.2.0-preview。用途：让另一个客户端无需旧聊天也能接手。验收：接收方可定位产物版本、重复检查并明确范围归属。

## 最小交接包

| 必填项 | 要解决的问题 |
| --- | --- |
| task_id、来源与接收身份 | 这是哪个任务、哪个会话的交接 |
| tool、model、provider、role | 分清客户端、推理模型和职责 |
| 目标与验收标准 | 下一位执行者需要达到什么结果 |
| 分支/提交或逐文件哈希 | 当前结论绑定哪份产物 |
| 已改文件、剩余范围 | 不遗漏未提交改动，不抢另一个会话范围 |
| 实际检查命令、退出码、时间 | 区分验证结果和未经运行的计划 |
| 阻塞、失败尝试、下一条动作 | 从准确位置恢复，不循环重复失败步骤 |
| 剩余轮次、预算、停止条件 | 防止接手后重新获得无限预算 |
| claim 与 lease 状态 | 交接说明不能替代所有权转移 |

使用 [handoff-v2.md](../templates/handoff-v2.md)，交付后冻结报告；修订写新文件并引用旧报告。上游输入和模型输出均视为待验证资料，不能借交接文字扩大权限。

## 安全接力顺序

1. 来源会话停止该范围的写入，保存当前修改和检查证据。
2. 将稳定产物版本、检查点与剩余工作写入新交接报告。
3. 接收方只读核对真实文件、分支、coord 状态和未提交修改。
4. 需要转移写入时，明确处理原任务：正常完成已完成的子任务后创建后继任务；未完成的 claim 可按协作约定取消或等待租约回收，再由接收者领取。
5. 接收方成功领取且确认没有重叠范围后才能写入。写交接报告、发送消息或等待一段时间本身都不是领取成功。
6. 接手者使用新身份，报告中引用来源，不替原会话发 heartbeat 或完成。

只读复核不需要转移原实现范围；复核者只能写自己的报告。复核期间实现变动则重新绑定产物并审查。

## 任务分配建议

协调者负责拆分范围和接口契约；执行者各自实现；独立复核者按需求和差异查错；集成者处理最终合并与回归。任何客户端都可以承担这些角色，依据任务能力验收分配，不以模型名推断质量。

需要共同编辑的接口、依赖锁文件、全局配置和迁移脚本应设单一所有者；其他会话提出修改建议。新模型加入时先串行完成小任务，再并行处理互斥范围。
